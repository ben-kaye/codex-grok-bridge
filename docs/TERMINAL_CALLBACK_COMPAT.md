# Terminal callback compatibility note

The bridge intentionally advertises ACP `terminal: false` so Grok Build owns command execution, but if client-hosted terminals are reintroduced, account for a Grok Build 1.0.x wire quirk: on Unix it may send a complete shell invocation such as `/bin/bash -lc 'printf "hello world\n"'` in `CreateTerminalRequest.command` with an empty `args` array, which cannot be passed directly to `Command::new`; normalize only this form at the process boundary by shell-splitting `command` when `args` is empty and the first token is a recognized shell (`sh`, `bash`, `dash`, `zsh`, `fish`, or `ksh`), reject malformed quoting, and otherwise preserve ACP's structured `command` plus `args` exactly, with focused tests for quoted pipelines, unchanged structured arguments, malformed input, process output, exit status, timeout/kill, release, approval, and sandbox behavior.
